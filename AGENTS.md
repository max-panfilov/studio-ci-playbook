# Инструкции для агентов

## Назначение

Репозиторий — публичный документарный playbook о CI/CD, а не копия production-системы. Здесь нет исполняемого Studio CI, watcher, deployment credentials или готового pipeline для внедрения без адаптации.

Разделяйте три статуса:

- **общая одобренная политика** — build once на доверенном self-hosted CI, неизменяемые проверенные артефакты, независимые promotion gates, разделённые credentials и безопасность данных;
- **наблюдаемая реализация** — датированное описание пяти компонентов и двух слоёв выбора области, а не текущий live-статус;
- **синтетические примеры** — учебные документы с `synthetic: true` и `evidence: false`, которые ничего не доказывают о реальной системе.

## Границы

Не добавляйте бинарный `.pyz`, watcher, частные политики, production topology, реальных principals, полные SHA/digests, журналы, request UUID, snapshots, клиентские сведения и credentials. Не копируйте частную Git history или длинные операционные протоколы. Правила обезличивания — в `SANITIZATION.md`.

Текущий описанный workflow запускается по push/dispatch. Не обещайте универсальный PR/preview service, универсальное соответствие native-release всем проектам, нулевое число уязвимостей, мониторинг CVE работающих образов или гарантированное восстановление. Content-only release — отдельный маршрут.

## Редактура и схемы

Русский текст пишите ясно, с «ёлочками», длинным тире, коротким тире в диапазонах, неразрывными пробелами после однобуквенных предлогов и десятичными запятыми. Код, идентификаторы и имена полей оставляйте английскими. Датированные измерения не называйте SLA.

Mermaid храните только inline в Markdown. Подписи узлов заключайте в кавычки. После изменения примеров обновите `schemas/examples.schema.json`, тесты и связанные документы. Публичная схема намеренно иллюстративна и не совместима по умолчанию с частной схемой Studio CI.

`pyproject.toml` содержит только зависимости проверки. Не добавляйте application dependencies. `uv.lock` генерируется на доверенном CI и коммитится для воспроизводимого `uv sync --frozen`.

## Проверка

Не заявляйте проверки без фактического результата. Полный контроль выполняйте на доверенном self-hosted runner через `ci/verify.sh`; не добавляйте GitHub-hosted fallback. Состав и границы проверок описаны в `docs/verification.md`.

Перед pull request проверьте diff, обезличивание, относительные ссылки, fences, Mermaid, JSON Schema и YAML 1.2. Синтаксис YAML не означает принятие workflow Gitea, а структурная проверка Mermaid не заменяет просмотр рендеринга.
